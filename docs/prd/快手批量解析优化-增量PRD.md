### 产品目标（3 条，正交）

- **G1 可用性**：付费接口失败、字段不兼容或直链服务不可用时，仍能通过免费兜底把作者公开作品（视频 + 图集）批量解析成可下载地址；可度量判据为「批量结果不再出现 0 条 / 只剩第一页 / 整批暂缺下载地址」。

## 1. 一句话目标 + 背景

**目标**：让现有「视频下载」页的快手批量链路，在付费采集接口失败、返回字段不兼容或免费直链服务不可用时，仍能通过**免费移动端 SSR 首屏兜底 + 统一结构归一化**把作者公开作品（视频与图集）批量解析成可下载地址，并把每一步的真实结果与失败原因明明白白显示给客户。

**背景**：工程已有快手两段式批量链路（`_resolve_kuaishou_uid()` → `list_kuaishou_blogger_videos()` → `_to_video_info_p("kuaishou", raw)` → 缺直链走 `media_parser.parse()` 补），但链路长、降级不可见、失败文案笼统（「该账号可能没有公开作品」），客户与售后都无法判断卡在哪一段。用户提供的拆解文档给出的是「不逆向签名，三条数据通道 + 逐级降级 + 结构归一化」的路线，其价值不在「能解析快手」，而在**用多个数据源拼出同一个业务能力**并配套归一化层、任务状态、断点续传与「产品层面承认技术边界」的文案处理。本轮取其思路，不搬其架构。

## 4. 用户故事

1. **作为**用快手博主主页链接批量下载的客户，**我希望**粘贴主页链接或 App 分享链接点「拉取列表」后能一次性拿到该作者公开作品并逐条可下载，**以便**不再出现「批量一条都解析不出来」。
2. **作为**一次要处理多位博主的客户，**我希望**多位博主串行拉取时某一位失败不影响其他位，并且能看到每位成功几条、失败原因是什么，**以便**不用整批重跑、也知道该找谁反馈。
3. **作为**想保存图集作品的客户，**我希望**快手图集作品能被识别成多张图片分别下载、与视频作品分开处理，**以便**「音视频（作品）」不再因拿不到视频直链而被当成失败。
4. **作为**网络不稳定或下载大文件的客户，**我希望**下载中断后能从已下载部分继续、且能随时点「停止」结束本次任务，**以便**不必整条重下、也不必等它自己跑完。
5. **作为**遇到问题后要找售后的客户，**我希望**界面直接告诉我「列表走了哪条通道、拿到几条、几条缺直链、为什么缺、下一步该做什么」，**以便**不用反复截图猜「是不是我链接贴错了」。
6. **作为**使用免费通道的客户，**我希望**界面明确告诉我「当前展示的是作者最新公开作品（免费通道仅首屏）」，**以便**不会误以为软件把我的数据偷偷抓少了，也知道想要历史作品该怎么做。

## 6. UI 文案与交互变更（现有「视频下载」页内，不新增页面）

### 6.1 首屏边界明示（P0-7）

- 兜底生效时状态行追加：
  > 已展示这位作者最新的公开作品（免费通道只能拿到首屏）。想抓更早的历史作品，请切回完整采集通道，或把单条作品链接粘贴到解析框。
- **禁止**在该提示里出现「额度 / 余额 / 暂不支持 / 需激活 / 激活授权码 / 填写 API Token」任何字样；免费版状态栏禁「额度」。
- 不得把「已拉取 N 条」当完整结果展示而不带首屏说明。

### 6.2 降级原因上屏（P0-6）

- 列表收尾说明由单一「快手作品 N 条」升级为分段说明，例如：
  > 列表：完整采集通道 20 条（第 2 页起改走免费首屏兜底 12 条）；直链：18 条已就绪、2 条待重试（解析服务限流，等一两分钟再跑剩下这些）。
- 完整采集通道自身的错误提示沿用现有 `recharge_hint` 按通道显示机制；**一旦触发免费兜底，界面只呈现「已自动切换到免费通道（首屏）」与结果条数，不叠加任何 Key/余额/激活类字样**。

### 6.3 进度与取消（P1-3）

- 进度文案分三段：「正在拉取第 X 页…」「正在补第 i/N 条直链…」「正在下载第 j/M 条…」；多博主沿用 `_SegmentWorker` 的「第 X/Y 位」。
- 运行中按钮文案改为「停止」并**保持可点击**，点击后取消当前批量任务；运行中的防重复提交沿用现有做法。
- **付费闸门相关主按钮一律可点**：点了弹须知，不得用 `setEnabled(False)` 代替 `require_feature(...)`；本轮不新增付费动作，既有付费动作的 `require_feature(...)` 位置保持为主动作第一行，不得挪后或删除。

### 6.4 失败原因分级（P0-6，客户能照着做的一句话）

| 类别 | 建议文案 |
|---|---|
| 配置/通道类 | 「已自动切换到免费通道（首屏）」（兜底生效时只说这句，不提 Key/余额） |
| 网络类 | 「网络没连上或超时了 —— 换条网络，或稍后再试这一条」 |
| 限流类 | 「解析服务正在限流 —— 等一两分钟再跑剩下这些」 |
| 内容类 | 「这条作品可能已被删除或设为私密」 |
| 结构类 | 「快手页面结构变了，免费通道暂时读不到 —— 请把这条链接反馈给作者」 |
| 链接类 | 「没认出快手主页链接 —— 请复制博主主页链接或 App 里的分享链接再粘」 |
| 空结果（仅双重确认后） | 「已确认这位作者暂无公开作品」 |

- 明确废弃：把「该账号可能没有公开作品」「列表为空（可能该账号未公开或确实为空）」当作任何失败的默认兜底文案。

## 7. 明确不做的边界

1. **不逆向快手签名**：不实现 `sig4` / `a_bogus` 类算法，不因签名问题引入新依赖。
2. **不做扫码登录**：不引 `kuaishou_auth.py` 那套 Playwright 扫码、不落 Cookie、不碰 P0 隐私红线。
3. **不新增页面**：优先活化现有「视频下载」页；不改 `gui_qt/page_registry.py` 的 `PAGES`，不跑 `gen_pages.py`。
4. **不引入新付费接口**：免费 SSR 兜底属「列表采集通道内部的免费数据源」，零成本、不进闸门、不新增 `ENDPOINT_MAP` 映射；完整采集通道仍为默认。
5. **不改三链路分工**：① 采集/列表 → `okdata`（默认，用户自填 `okd_` Key，可切回旧通道）；② 视频/图文直链 → `video.zacao.top`（免费、不进付费闸门）；③ 直播录制 → 本地 ffmpeg。三者绝不混用，两个 Key 不混。
6. **不擅自发版**：只落工作区，不打包、不 push、不发版、不升版本号；PRD 不含任何对外动作。
7. **附加边界**：不引入 Playwright/Chromium 新依赖、不引入代理池评分、不改其他平台链路、不改既有落盘目录与命名规则、不新增全局单例任务状态机、不新增功能位（见第 8 节 Q4）。
